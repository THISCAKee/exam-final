# ระบบสอบออนไลน์ 80 ข้อ

Next.js 16 / React 19 ใช้คำถามจาก `Student_Exam_80Q.docx` และเฉลยจาก `Teacher_Answer_Key.pdf` คะแนนเต็ม 80 คะแนน เวลา 60 นาที สุ่มลำดับคำถามและตรวจคะแนนฝั่งเซิร์ฟเวอร์ ตรวจชื่อ–นามสกุลหรือรหัสนิสิตซ้ำกับผลสอบใน Google Sheets โดยไม่ต้องใช้ Turso

## เริ่มใช้งาน

ใช้ Node.js 22.20 ขึ้นไป

```bash
npm ci
cp .env.example .env.local
```

หากตั้งค่า `.env.local` แล้ว ไม่ต้องคัดลอกทับ

## เชื่อม Google Sheets

ปลายทาง: [Exam_Final แท็บ exam-final-69](https://docs.google.com/spreadsheets/d/13NQODP2AuJpSjrlBAYSP1Nn2qDJ7XfA-HYUEqviODnE/edit?gid=1872488623#gid=1872488623)

1. เปิด Google Sheets API ใน Google Cloud project ของ Service Account
2. สร้างหรือใช้ Service Account ที่มีอยู่ และดาวน์โหลด JSON key มาเก็บไว้นอก repository
3. แชร์สเปรดชีตให้ `client_email` ของ Service Account ด้วยสิทธิ์ Editor
4. ตั้งค่าโดยระบุไฟล์ JSON บนเครื่อง:

```bash
node scripts/configure-google.mjs /absolute/path/service-account.json
npm run dev
```

สคริปต์จะสร้าง `.env.local` และไม่พิมพ์ private key ออกทางหน้าจอ ไฟล์นี้ถูก gitignore ไว้แล้ว หากนำขึ้นโฮสต์ ให้เพิ่มตัวแปรทั้ง 4 จาก `.env.example` ใน environment ของโฮสต์ ห้ามใช้คำนำหน้า `NEXT_PUBLIC_` กับ credentials

API เลือกแท็บด้วย `GOOGLE_SHEET_GID=1872488623` จึงไม่บันทึกลง Sheet1 โดยผิดพลาด แม้ชื่อแท็บจะเปลี่ยน ระบบตรวจหัวตารางก่อนเขียน และเติมหัว Q61–Q80 ให้แท็บเก่าที่มี Q1–Q60 ได้

คอลัมน์ A–CH: `Timestamp, FirstName, LastName, StudentID, Section, Score, Q1, …, Q80` คะแนนเป็นตัวเลข ส่วนรหัสนิสิตและกลุ่มเรียนเก็บเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า คำตอบ Q1–Q80 เรียงตามเลขข้อในเอกสารต้นฉบับ แม้ผู้สอบจะได้รับคำถามคนละลำดับ

ระบบเริ่มสอบผ่าน `/api/attempts/start` โดยอ่านผลสอบในแท็บที่ระบุด้วย `GOOGLE_SHEET_GID` ถ้าพบชื่อ–นามสกุลเต็มหรือรหัสนิสิตซ้ำ จะไม่ให้เข้าสอบ โดยปรับรูปแบบตัวอักษรและช่องว่างก่อนเปรียบเทียบ ชื่อจริงที่เหมือนกันแต่นามสกุลและรหัสนิสิตต่างกันยังสอบได้ หากอ่านชีตไม่สำเร็จจะไม่อนุญาตให้เริ่มสอบ

เซิร์ฟเวอร์ออก token ที่ลงลายเซ็นด้วย HMAC เก็บตัวตน ลำดับข้อ และเวลาสิ้นสุดไว้ใน token เพื่อให้ใช้กับ Vercel หลาย instance ได้โดยไม่ต้องมีฐานข้อมูล ห้ามเปลี่ยน private key ระหว่างมีผู้กำลังสอบ คำตอบอยู่ในหน่วยความจำของหน้าเว็บระหว่างทำข้อสอบ ไม่มีการบันทึกทุกครั้งที่เลือกคำตอบหรือ heartbeat

เมื่อส่งคำตอบ API ตรวจลายเซ็น token และตรวจคะแนนด้วยเฉลยฝั่งเซิร์ฟเวอร์ ตรวจข้อมูลซ้ำในชีตอีกครั้งก่อนเขียน ไม่เชื่อชื่อ รหัสนิสิต ลำดับข้อ คะแนน หรือ deadline ที่ส่งมาแยกจาก token จะแสดง “บันทึกผลสอบแล้ว” ต่อเมื่อ Google Sheets ตอบกลับว่าสำเร็จ หากล้มเหลวให้กดส่งใหม่ คอลัมน์ CI ชื่อ `AttemptID` ใช้ตรวจการส่งซ้ำจากรอบเดิมเพื่อไม่เพิ่มแถวหรือแก้คะแนนเดิมเมื่อส่งซ้ำตามลำดับ

## การติดตั้งบน Vercel

ตั้งค่าตัวแปร `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_GID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` สำหรับ Production แล้ว Redeploy รองรับ `GOOGLE_SERVICE_ACCOUNT` เป็นชื่อเดิมของตัวแปรอีเมลด้วย โดยค่าต้องเป็นอีเมล Service Account ไม่ใช่ JSON ทั้งไฟล์ ใช้ `GOOGLE_SERVICE_ACCOUNT_EMAIL` เป็นหลักหากตั้งไว้ทั้งสองชื่อ

ไม่ต้องตั้งค่า `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `EXAM_DB_PATH` หรือ cron สำหรับ flow นี้ โมดูล SQLite/Turso และสคริปต์ย้ายข้อมูลเดิมยังเก็บไว้สำหรับข้อมูลเก่า แต่ API สอบไม่ได้ใช้แล้ว ข้อมูลในฐานข้อมูลเก่าที่ไม่เคยส่งเข้าชีตจะไม่ถูกนำมาตรวจซ้ำ

เมื่อหมดเวลา หน้าเว็บส่งคำตอบอัตโนมัติ อนุโลมเวลาเครือข่าย 60 วินาที เมื่อออกจากหน้าหรือรีเฟรช เบราว์เซอร์พยายามส่ง exit beacon พร้อมคำตอบล่าสุด แต่ไม่รับประกันหากปิดโปรแกรมหรือขาดอินเทอร์เน็ต จึงควรส่งคำตอบและรอการยืนยันก่อนปิดหน้า ไม่มีคิวส่งซ้ำหรือการปิดรอบจากเซิร์ฟเวอร์เมื่อผู้สอบออฟไลน์

การตรวจซ้ำอ้างอิงเฉพาะแถวที่บันทึกในชีตแล้ว ไม่จองสิทธิ์ตั้งแต่เริ่ม และไม่มี transaction สำหรับอ่านแล้วเขียน ผู้สอบเดิมจึงอาจเริ่มจากสองเครื่องก่อนมีผลสอบ หรือเกิดแถวซ้ำเมื่อส่งพร้อมกันได้ การป้องกันกรณีนี้ต้องเพิ่มตัวกลางที่ล็อกการทำงานหรือใช้ฐานข้อมูลภายหลัง การลบแถวผลสอบจะทำให้เข้าสอบใหม่ได้
